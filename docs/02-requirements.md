## 1. 背景と課題

| # | 現状の課題 | 影響 |
|---|---|---|
| P1 | Google広告・Yahoo!広告・Meta広告・Search Console・GA4・X・Instagram などを **個別の管理画面** で確認している | 全体像が見えず、チャネル間の比較・判断に時間がかかる |
| P2 | 既存ダッシュボード（GA / Google広告 / SEO / SEO・GEO・AIO・LLMO / SNS）が **それぞれ独立** している | 同じ指標でも定義や期間がそろわない |
| P3 | 「どんなユーザーに・どのチャネルで・どんな訴求をすると成果が出るか」が **ツールをまたいで見えない** | 認知系チャネル（SNS など）が過小評価され、予算配分が偏る |
| P4 | 分析結果が **施策の実行・効果検証に結びつかない** | 分析して終わりになり、PDCA が回らない |
| P5 | 企業ごとに使うツールが違い、**後からツールが増える**（例：Yahoo!広告を始めたい） | 都度ダッシュボードを作り直すコストがかかる |

## 2. 目的とゴール

| ゴール | 成功指標（KPI） |
|---|---|
| G1. 全チャネルの成果を 1 画面で把握できる | 定例レポート作成時間 50% 削減 |
| G2. カスタマージャーニー上の有効な接点とセグメント別の勝ち筋が分かる | 施策のうち「セグメント×チャネル根拠あり」の割合 80% 以上 |
| G3. 分析から施策起票・効果検証までを同じ基盤で回せる | 月あたり起票施策数、効果検証完了率 |
| G4. 既存ダッシュボードを捨てずに統合できる | 既存 5 ダッシュボードの統合完了（段階1: 即日、段階2: Phase 2 内） |
| G5. 企業ごとにモジュールを後から追加できる | 新規標準モジュール追加の開発工数 1 人日以内、カスタムモジュールはノーコード |

## 3. 利用者

| ロール | 主な利用シーン | 主に使う画面 |
|---|---|---|
| マーケティング責任者（CMO / 部長） | 全体の成果把握、予算配分の意思決定 | コマンドセンター、戦略プランナー |
| チャネル担当（広告・SEO・SNS 運用） | 担当チャネルの詳細確認、施策の実行 | チャネル別ページ、施策ボード |
| アナリスト / ストラテジスト | ジャーニー・セグメント分析、戦略立案 | カスタマージャーニー、オーディエンス分析 |
| 支援会社（代理店・コンサル） | 複数クライアント（企業）の横断管理 | ワークスペース切替、モジュールカタログ |
| 管理者 | 企業の追加、モジュール接続、権限管理 | 設定、モジュールカタログ |

## 4. スコープ

| 区分 | Phase 1（MVP・本リポジトリ） | Phase 2 以降 |
|---|---|---|
| 画面 | 全画面（§5）をサンプルデータで動作 | 実データ接続 |
| 連携 | 埋め込み（URL）、JSON/CSV ブリッジ、サンプルデータ | OAuth による API 自動取得 |
| インサイト | ルールベース | 生成AIによる文章化・戦略提案 |
| 実行 | 施策ボード（起票・進行管理） | 広告・配信ツールへの反映（承認フロー付き） |
| 認証・権限 | なし（単一利用者、ブラウザ保存） | SSO、ロール、監査ログ |

## 5. 機能要件

優先度：**Must**（MVP 必須）/ **Should**（MVP で可能な範囲）/ **Could**（Phase 2 以降）

### 5.1 ワークスペース（企業）管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-WS-01 | 複数の企業（ワークスペース）を登録し、画面上部で切り替えられる | Must |
| FR-WS-02 | ワークスペースごとに、業種・事業モデル（BtoB/BtoC）・KGI（種類と目標値）・月間広告予算を設定できる | Must |
| FR-WS-03 | ワークスペースごとに有効なモジュールが異なり、ナビゲーション・分析対象が連動する | Must |
| FR-WS-04 | ワークスペースごとに顧客セグメント（ペルソナ）を定義・編集できる | Must |
| FR-WS-05 | テンプレート（BtoB / EC / 地域ビジネス）から新規ワークスペースを作成できる | Should |
| FR-WS-06 | メンバー招待とロール（Owner / Admin / Editor / Viewer）管理 | Could |

### 5.2 モジュール（プラグイン）管理

| ID | 要件 | 優先度 |
|---|---|---|
| FR-MD-01 | 利用可能なモジュールをカテゴリ別に一覧表示するカタログを持つ | Must |
| FR-MD-02 | カタログからモジュールを追加（有効化）・停止できる。追加は接続ウィザード経由 | Must |
| FR-MD-03 | 追加したモジュールは、サイドバー・全体KPI・ジャーニー・アトリビューション・セグメント分析・予算シミュレーターに **自動で反映** される | Must |
| FR-MD-04 | 既存ダッシュボードの URL を登録し、モジュール内で埋め込み表示・別タブ表示できる | Must |
| FR-MD-05 | JSON / CSV（ブリッジ形式）でデータを取り込み、モジュールのデータとして扱える | Must |
| FR-MD-06 | 画面操作だけで「カスタムモジュール」（名称・カテゴリ・担当段階・埋め込みURL・データ）を作成できる | Must |
| FR-MD-07 | 標準モジュールとして最低限 GA4 / Google広告 / SEO / AI検索（GEO・AIO・LLMO）/ SNS / Yahoo!広告 / Meta広告 / LINE広告 / TikTok広告 / Googleビジネスプロフィール / メール・MA / CRM を用意する | Must（定義）/ Could（実接続） |
| FR-MD-08 | 各モジュールの接続状態（接続済み・サンプル・要再認証・エラー）を表示する | Should |

### 5.3 コマンドセンター（全体ダッシュボード）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-CC-01 | KGI（売上 or CV 数）の実績・目標・達成率を最上部に表示する | Must |
| FR-CC-02 | 全チャネル合算の主要指標（費用・CV・CPA・ROAS・セッション）を前期間比付きで表示する | Must |
| FR-CC-03 | 期間（7 / 28 / 90 日）を切り替えられ、全画面に反映される | Must |
| FR-CC-04 | 日別推移をチャネル別に表示する | Must |
| FR-CC-05 | チャネル別の成果表（費用・CV・CPA・ROAS・前期比）を表示する | Must |
| FR-CC-06 | ジャーニー段階別のファネルを表示する | Must |
| FR-CC-07 | 異常検知アラートと優先度の高いインサイトを表示する | Must |

### 5.4 カスタマージャーニー

| ID | 要件 | 優先度 |
|---|---|---|
| FR-JR-01 | 段階（認知→興味・関心→比較・検討→CV）ごとに、どのチャネルからどのチャネルへ顧客が流れたかをフロー図で表示する | Must |
| FR-JR-02 | フロー図は顧客の動きが分かるアニメーションを持つ | Must |
| FR-JR-03 | セグメントで絞り込める | Must |
| FR-JR-04 | CV に至った接点経路の上位を、人数・CVR・平均所要日数付きで表示する | Must |
| FR-JR-05 | アトリビューションモデル（5 種）を切り替え、チャネル別の貢献度を比較できる | Must |
| FR-JR-06 | 段階別の離脱率を表示し、最大の離脱箇所を示す | Should |

### 5.5 オーディエンス分析（誰に・何を・どこで）

| ID | 要件 | 優先度 |
|---|---|---|
| FR-AU-01 | セグメント × チャネルの CVR 指数（全体平均 = 100）をヒートマップで表示する | Must |
| FR-AU-02 | 列を「チャネル」と「訴求軸（価格・事例・機能・限定・共感）」で切り替えられる | Must |
| FR-AU-03 | セルを選ぶと、そのセグメント×アプローチの詳細（CV・CPA・推奨アクション）を表示する | Must |
| FR-AU-04 | 詳細から施策ボードへ起票できる | Must |
| FR-AU-05 | 各セグメントの「勝ちパターン」（最適チャネル × 最適訴求）を一覧表示する | Should |

### 5.6 戦略プランナー

| ID | 要件 | 優先度 |
|---|---|---|

| FR-ST-02 | 有料チャネルの予算をスライダーで配分し、予測 CV・CPA を即時に再計算する | Must |
| FR-ST-03 | 「最適配分」を実行すると、総予算内で予測 CV が最大となる配分を提示する | Must |
| FR-ST-04 | チャネル別の応答曲線（予算と CV の関係）を表示する | Should |
| FR-ST-05 | 配分案を施策として起票できる | Should |

### 5.7 施策ボード（実行管理）

|---|---|---|
| FR-EX-01 | 施策をカンバン（企画中 / 準備中 / 実行中 / 効果検証 / 完了）で管理する | Must |
| FR-EX-02 | ドラッグ＆ドロップでステータスを変更できる | Must |
| FR-EX-03 | 施策に対象モジュール・セグメント・ジャーニー段階・KPI・担当・期限・期待効果を持たせる | Must |

| FR-EX-05 | 施策を作成・編集・削除できる | Must |

### 5.8 AIインサイト

| ID | 要件 | 優先度 |
|---|---|---|

| FR-IN-03 | 提案から施策ボードへ起票できる | Must |

### 5.9 チャネル別ページ

| ID | 要件 | 優先度 |
|---|---|---|
| FR-CH-01 | 有効な各モジュールに専用ページを自動生成する（KPI・推移・内訳） | Must |
| FR-CH-02 | 既存ダッシュボードタブ（埋め込み・別タブで開く・URL 登録） | Must |

## 6. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 性能 | 画面遷移・期間切替・フィルタ操作は 300ms 以内に再描画（90 日 × 10 モジュール規模） |
| NFR-02 | 操作性 | PC（1280px〜）を主対象、タブレット・スマートフォン（〜400px）でも閲覧可能 |
| NFR-03 | 表示 | ライト / ダークモード対応。色だけに頼らない表示（ラベル・アイコン併記） |
| NFR-04 | アクセシビリティ | キーボード操作可能、フォーカス可視、`prefers-reduced-motion` でアニメーション抑制 |
| NFR-05 | 拡張性 | 標準モジュール追加はマニフェスト 1 ファイル＋登録 1 行。コア改修不要 |
| NFR-06 | 保守性 | 分析ロジックは DOM 非依存の純粋関数で、単体テストを持つ |
| NFR-07 | セキュリティ | 認証情報はフロントエンドに保持しない（Phase 2 は BFF で暗号化保管）。埋め込みは https のみ、sandbox 付き |
| NFR-08 | データ品質 | 取り込みデータはスキーマ検証し、拒否理由を利用者に示す |
| NFR-09 | 可用性（Phase 2） | 稼働率 99.5%、日次同期の失敗は再試行し通知 |
| NFR-10 | 多言語 | 日本語 UI。指標名・通貨（円）は日本の慣習に合わせる |

## 7. 制約・前提

- MVP はサンプルデータ（シード固定の合成データ）で全画面を動作させる。数値は実在企業のものではない。
- 既存 5 ダッシュボードのソースは本リポジトリ外にあるため、MVP では「段階1：埋め込み」と「段階2：ブリッジ形式の受け口」を用意し、実データ接続は Phase 2 で行う。
- 外部 API（Google Ads API、Yahoo!広告 API、Meta Marketing API、GA4 Data API、Search Console API、X API、Instagram Graph API など）の利用には各社の審査・利用規約への同意が必要。

## 8. 受け入れ基準（Phase 1）

| # | 基準 |
|---|---|
| AC-1 | 3 つのサンプル企業を切り替えると、ナビゲーション・数値・ジャーニーが企業ごとに変わる |
| AC-2 | カタログから Yahoo!広告を追加すると、サイドバー・コマンドセンター・ジャーニー・予算シミュレーターに即時反映される |
| AC-3 | 既存ダッシュボードの URL を登録すると、該当モジュールで表示・別タブ表示できる |
| AC-4 | ブリッジ形式の JSON/CSV を取り込むと、そのモジュールの数値が置き換わる。不正行は理由付きでスキップされる |
| AC-5 | カスタムモジュールを画面から作成でき、ジャーニーに段階どおりに表示される |
| AC-6 | インサイト・セグメント分析・予算配分から施策を起票でき、カンバンで移動できる |
| AC-7 | 分析エンジンの単体テストがすべて通る |
